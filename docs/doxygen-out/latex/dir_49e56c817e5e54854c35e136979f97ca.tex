\doxysubsection{Detailed Description}
\hypertarget{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md0}{}\doxysubsection{\texorpdfstring{RBus}{RBus}}\label{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md0}
RBus (RDK Bus) is a lightweight, fast, and efficient inter-\/process communication (IPC) framework used across RDK middleware. It allows multiple processes running on a hardware device to communicate through remote procedure calls (RPC), property get/\+set operations, and event-\/based messaging. RBus supports the creation and use of a hierarchical data model — a named tree of objects with properties, events, and methods — making it suitable for implementing parameter management specifications such as TR-\/181.

RBus follows a provider-\/consumer model. Providers register named objects, properties, events, and methods in the data model and implement the corresponding handlers. Consumers look up and interact with those elements across process boundaries. A single process can act as both a provider and a consumer simultaneously. The central message-\/routing daemon, {\ttfamily rtrouted}, serves as the broker through which all inter-\/process messages flow, decoupling components from direct peer-\/to-\/peer communication.

The framework is applicable across RDK middleware deployments covering both broadband and video platforms. On broadband platforms it serves as the backbone IPC mechanism for components such as protocol agents, network managers, and configuration services. On video platforms, RBus is used primarily by the telemetry subsystem for event notification.

{\bfseries{Key Features \& Responsibilities:}}


\begin{DoxyItemize}
\item {\bfseries{Property Access}}: Provides synchronous {\ttfamily get} and {\ttfamily set} operations over named, dot-\/separated parameter paths, supporting the full TR-\/181 naming convention including wildcards and instance notation ({\ttfamily \{i\}}).
\item {\bfseries{Remote Method Invocation}}: Supports both synchronous and asynchronous remote procedure calls with structured input and output parameter marshalling, configurable timeouts, and error propagation back to the caller.
\item {\bfseries{Event System}}: Implements a publish-\/subscribe mechanism for value-\/change detection, table row creation/\+deletion, interval-\/based notifications, and provider-\/defined general events. Subscriptions support optional filters and duration limits.
\item {\bfseries{Hierarchical Data Model}}: Manages a named tree of elements (properties, objects, tables, methods, events) that providers register and consumers traverse or query, including wildcard discovery.
\item {\bfseries{Central Message Routing}}: The {\ttfamily rtrouted} daemon routes all messages between registered components, enabling loose coupling. Clients connect to the daemon rather than to each other directly.
\item {\bfseries{Session Management}}: The {\ttfamily rbus\+\_\+session\+\_\+mgr} service allocates session identifiers that can be used to serialise multi-\/step set operations (commit/\+rollback behavior depends on provider implementation).
\item {\bfseries{Optional Transport Security}}: Supports SPAKE2+ key exchange to derive a shared key that is then used to encrypt messages between the router and clients (AES) when built with the corresponding compile-\/time option.
\item {\bfseries{Subscription Persistence}}: Caches active subscriptions to a temporary directory so that they can be restored automatically after a provider restarts, avoiding the need for consumers to re-\/subscribe.
\end{DoxyItemize}

\hypertarget{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md2}{}\doxysubsection{\texorpdfstring{Design}{Design}}\label{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md2}
RBus is structured as a layered C library with a clear separation between the public API, the core message-\/processing engine, the low-\/level transport, and supporting services. The public API ({\ttfamily \doxylink{rbus_8h}{rbus.\+h}}) exposes all provider and consumer operations through opaque handle types, hiding all routing and serialisation details from callers. Internally, the core layer ({\ttfamily rbuscore}) translates API calls into typed messages serialised with Message\+Pack and forwards them through the RT Message transport layer to {\ttfamily rtrouted}, which routes each message to the appropriate destination process. This hub-\/and-\/spoke topology means that every component connects only to the central daemon, with all message routing handled centrally.

Northbound, the API layer presents a unified C interface covering property get/\+set and table management operations used in data model-\/driven middleware as well as event-\/driven patterns used by application and media middleware. Southbound, the RT Message transport layer provides the connection management, socket lifecycle, and message framing needed to communicate with {\ttfamily rtrouted}. Hardware-\/specific values are accessed by the provider component through its own HAL before being exposed via the data model.

Data persistence is handled externally. RBus itself writes subscription state to a temporary directory ({\ttfamily RBUS\+\_\+\+TMP\+\_\+\+DIRECTORY}, default {\ttfamily /\+tmp}) so that subscriptions survive provider restarts. Persistent parameter values are the responsibility of each provider component, which may use the platform\textquotesingle{}s persistent storage facilities independently of RBus.

The northbound interface is the C API defined in {\ttfamily \doxylink{rbus_8h}{rbus.\+h}}, which components include to open connections, register data elements, and invoke or respond to remote operations. The southbound interface is the {\ttfamily rt\+Connection} abstraction, which wraps the socket-\/level communication with {\ttfamily rtrouted}. \begin{DoxyItemize}
\item {\bfseries{Threading Architecture}}: Multi-\/threaded with per-\/handle and per-\/element synchronisation.
\item {\bfseries{Caller Threads}}: Call synchronous APIs such as {\ttfamily \doxylink{group___initialization_gacf19c7e46ff9c2353892f5918310b264}{rbus\+\_\+open}}, {\ttfamily \doxylink{group___consumers_ga4784460070e869774b9ed69d1b309571}{rbus\+\_\+get}}, {\ttfamily \doxylink{group___consumers_ga69f715cea76a0ea395c416a0a0bbe19b}{rbus\+\_\+set}}, {\ttfamily \doxylink{group___providers_ga58d4e15c31e566321fcbf96e4b4deace}{rbus\+\_\+reg\+Data\+Elements}}, and {\ttfamily \doxylink{group___initialization_ga9ccb6de1c606f5ac59dbc3a5a2ad0dd0}{rbus\+\_\+close}}. Only global handle-\/list operations and related callbacks are serialised with a process-\/wide mutex ({\ttfamily g\+Mutex}); most other concurrency control is handled via per-\/handle/\+per-\/element locks.
\item {\bfseries{Worker Threads}}:
\begin{DoxyItemize}
\item {\itshape Callback Thread} (one per {\ttfamily rt\+Connection}): Reads inbound messages from the socket and dispatches them to registered handlers. Created and managed within {\ttfamily rt\+Connection.\+c}.
\item {\itshape Thread Pool Workers} ({\ttfamily rt\+Thread\+Pool}): Processes asynchronous tasks submitted by the callback thread, including async method responses and subscription deliveries.
\item {\itshape Value Change Detector Thread}: Polls registered property nodes at a fixed 2000 ms interval to detect value changes and trigger {\ttfamily \doxylink{group___events_gga8572487d31c269212da91488e8eb33b9a433ddaf617d8570b2afd8a46dcabeefe}{RBUS\+\_\+\+EVENT\+\_\+\+VALUE\+\_\+\+CHANGED}} notifications to active subscribers.
\item {\itshape Async Subscribe Thread}: Manages subscription retry logic, backing off up to 60 000 ms between retries within a 600 000 ms total timeout window.
\end{DoxyItemize}
\item {\bfseries{Synchronization}}: Per-\/handle mutexes ({\ttfamily handle\+\_\+event\+Subs\+Mutex}, {\ttfamily handle\+\_\+subs\+Mutex}) protect the consumer and provider subscription lists respectively. Per-\/element mutexes ({\ttfamily elm\+Mutex}) serialise access to individual element nodes in the registration tree.

\hypertarget{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md7}{}\doxysubsubsubsection{\texorpdfstring{Initialization to Active State}{Initialization to Active State}}\label{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md7}
RBus transitions through a structured sequence from daemon startup through element registration to active message processing. The {\ttfamily rtrouted} daemon must be fully running before any component calls {\ttfamily \doxylink{group___initialization_gacf19c7e46ff9c2353892f5918310b264}{rbus\+\_\+open}}. The session manager connects to the daemon over RBus itself, so it blocks internally until the daemon is available even when started concurrently.

\hypertarget{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md8}{}\doxysubsubsubsection{\texorpdfstring{Runtime State Changes}{Runtime State Changes}}\label{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md8}
{\bfseries{State Change Triggers:}}


\begin{DoxyItemize}
\item A consumer calling {\ttfamily \doxylink{group___events_gab5889c0424ae3e4efb9208de22b92835}{rbus\+Event\+\_\+\+Subscribe}} causes the provider to record the subscription and begin detecting value changes or accepting event publications for that subscriber.
\item A subscriber process crash or clean disconnect triggers {\ttfamily rbus\+Subscriptions\+\_\+handle\+Client\+Disconnect}, which removes all subscriptions associated with that listener address without requiring explicit unsubscribe calls.
\item A provider process restart causes {\ttfamily rtrouted} to signal its clients; pending subscriptions are restored from the subscription cache file in {\ttfamily /\+tmp} when the provider re-\/registers its elements.
\item Under high message load, the thread pool in the transport layer absorbs bursty traffic through queuing, maintaining consistent component behavior.
\end{DoxyItemize}

{\bfseries{Context Switching Scenarios:}}


\begin{DoxyItemize}
\item When a component calls {\ttfamily \doxylink{group___initialization_ga9ccb6de1c606f5ac59dbc3a5a2ad0dd0}{rbus\+\_\+close}}, all registered elements are de-\/registered, all provider-\/side subscriptions are cleaned up, and the {\ttfamily rt\+Connection} to {\ttfamily rtrouted} is torn down.
\item A component may hold up to {\ttfamily RBUS\+\_\+\+MAX\+\_\+\+HANDLES} (16) simultaneous open handles, allowing a single process to register elements under multiple logical component names.
\end{DoxyItemize}

\hypertarget{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md19}{}\doxysubsection{\texorpdfstring{Implementation Details}{Implementation Details}}\label{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md19}
\hypertarget{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md20}{}\doxysubsubsection{\texorpdfstring{Key Implementation Logic}{Key Implementation Logic}}\label{dir_49e56c817e5e54854c35e136979f97ca_autotoc_md20}

\begin{DoxyItemize}
\item {\bfseries{Handle and Element Lifecycle}}: {\ttfamily \doxylink{group___initialization_gacf19c7e46ff9c2353892f5918310b264}{rbus\+\_\+open}} allocates a {\ttfamily \+\_\+rbus\+Handle} structure, establishes the {\ttfamily rt\+Connection} to {\ttfamily rtrouted}, registers the component name, and initialises an empty element tree and subscription registries. {\ttfamily \doxylink{group___initialization_ga9ccb6de1c606f5ac59dbc3a5a2ad0dd0}{rbus\+\_\+close}} reverses this sequence, de-\/registering all elements, cleaning up subscriptions, and releasing the connection. Up to 16 handles may be open simultaneously per process ({\ttfamily RBUS\+\_\+\+MAX\+\_\+\+HANDLES}). Core implementation in {\ttfamily rbus.\+c} and {\ttfamily rbus\+\_\+handle.\+c}; element tree operations in {\ttfamily rbus\+\_\+element.\+c}.
\item {\bfseries{Event Processing}}: Provider-\/side subscriptions are stored in {\ttfamily rbus\+Subscriptions\+\_\+t}, serialised to a file in {\ttfamily /\+tmp} under the component name for crash recovery. When a provider restarts and re-\/registers its elements, {\ttfamily rbus\+Subscriptions\+\_\+resubscribe\+Element\+Cache} reloads the file and re-\/activates matching subscriptions. Consumer-\/side subscriptions are stored in the handle\textquotesingle{}s {\ttfamily event\+Subs} vector; disconnecting subscribers are cleaned up automatically via {\ttfamily rbus\+Subscriptions\+\_\+handle\+Client\+Disconnect} when {\ttfamily rtrouted} delivers a client-\/disconnect advisory. Subscription retry for async subscriptions is managed in {\ttfamily rbus\+\_\+asyncsubscribe.\+c} with back-\/off up to {\ttfamily RBUS\+\_\+\+SUBSCRIBE\+\_\+\+MAXWAIT}.
\item {\bfseries{Error Handling Strategy}}: The {\ttfamily \doxylink{group___common_ga8fc1f9c96c061b20db5e56188296c8ef}{rbus\+Error\+\_\+t}} enumeration covers all error conditions from transport failures ({\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aa73fa6a352bc465672bb6dfd2b0271ead}{RBUS\+\_\+\+ERROR\+\_\+\+DESTINATION\+\_\+\+NOT\+\_\+\+FOUND}}, {\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aacc9db1e50b8109fa8c91744d52000638}{RBUS\+\_\+\+ERROR\+\_\+\+DESTINATION\+\_\+\+NOT\+\_\+\+REACHABLE}}) to validation errors ({\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aa9a1547d7a456c5a71f40dca3dc933ecd}{RBUS\+\_\+\+ERROR\+\_\+\+INVALID\+\_\+\+INPUT}}, {\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aa8c5f052671250be982fd245e4c69509c}{RBUS\+\_\+\+ERROR\+\_\+\+INVALID\+\_\+\+PARAMETER\+\_\+\+TYPE}}) and access control rejections ({\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aab95268db5752e57383de180c77d78fc9}{RBUS\+\_\+\+ERROR\+\_\+\+ACCESS\+\_\+\+NOT\+\_\+\+ALLOWED}}, {\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aac4125cfdc40b04fdee894b6be3993379}{RBUS\+\_\+\+ERROR\+\_\+\+NOT\+\_\+\+WRITABLE}}). Core-\/layer {\ttfamily rbus\+Core\+Error\+\_\+t} values are mapped to {\ttfamily \doxylink{group___common_ga8fc1f9c96c061b20db5e56188296c8ef}{rbus\+Error\+\_\+t}} by {\ttfamily rbus\+Core\+Error\+\_\+to\+\_\+rbus\+Error()} in {\ttfamily rbus.\+c}. Timeout handling uses {\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aab4d44c7302674778282781128274393b}{RBUS\+\_\+\+ERROR\+\_\+\+TIMEOUT}}; asynchronous method handlers that defer processing return {\ttfamily \doxylink{group___common_gga5db8b0d14b831805c31bbf454b7a935aa9db57791261df9863366b7b495bcd751}{RBUS\+\_\+\+ERROR\+\_\+\+ASYNC\+\_\+\+RESPONSE}}.
\item {\bfseries{Logging and Diagnostics}}: The logging subsystem ({\ttfamily rt\+Log}) supports DEBUG, INFO, WARN, ERROR, and FATAL levels, selectable at runtime via {\ttfamily rt\+Log\+\_\+\+Set\+Level}. The backend can be switched between the built-\/in handler and the RDK Logger via {\ttfamily rt\+Log\+\_\+\+Set\+Option}. The {\ttfamily rbuscli} interactive utility ({\ttfamily utils/\+rbuscli/}) allows operators to register data model elements, execute get/\+set/\+method/\+subscribe operations, and observe event deliveries from a shell, providing a diagnostic surface for integration testing and field debugging. When {\ttfamily MSG\+\_\+\+ROUNDTRIP\+\_\+\+TIME} is enabled, {\ttfamily rtrouted} records per-\/message entry and exit timestamps accessible via the {\ttfamily RTROUTED\+\_\+\+TRANSACTION\+\_\+\+TIME\+\_\+\+INFO} field.
\end{DoxyItemize}

Parameter value persistence is managed by each provider component independently. Subscription state is written to {\ttfamily /\+tmp} by {\ttfamily rbus\+\_\+subscriptions.\+c} to support provider process restarts within a boot session. This cache lives under {\ttfamily /\+tmp} (typically cleared on reboot) and is removed by the provider when no subscriptions remain.
